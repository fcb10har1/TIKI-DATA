# P4: integration, evaluation, and reproduction

P4 implements the integration layer described in [PRD.md](PRD.md). The official
starter, validator, and metric implementation remain unchanged. Run commands
from the repository root. All experiment directories must be new; use a new run
name instead of overwriting evidence.

## Setup and first verification

Tested environment: CPython 3.12 with the complete dependency pins in
`requirements-p4.txt`. The original starter requirements remain available.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-p4.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m tiki_data demo --out runs/demo
```

On Linux/macOS use `python3.12` and `.venv/bin/python` for the same commands.
The demo creates four short synthetic matches and runs all three adapter slots,
the validation comparison, algorithm freeze, a single-method held-out test, and
CSV reproduction. Its model is **not a trained TCN**, and its small example
Viterbi decoder is **not P3's production decoder**. `accuracy_evidence: false`
is retained in its reports. It proves the integration works, not possession
accuracy on football data.

## Full supplied-match CSV: one command

Put the restricted assets in the folders specified in [DATA.md](../DATA.md), or
set `$env:MTAH_DATA_DIR` to their parent directory. Then:

```powershell
.\.venv\Scripts\python.exe -m tiki_data run --config configs/baseline.json --out runs/v1-rules
```

This reads tactical ATD metadata and tracking, runs the official nearest-player
baseline with its published ±50-frame smoothing setting, and writes
`runs/v1-rules/submission.csv`. It checks every raw ATD frame ID and validates
the resulting full CSV through the official metric library. It never reads
ground truth during inference. Missing assets are an error, recorded in
`run.json`; no fallback CSV is fabricated.

```powershell
.\.venv\Scripts\python.exe evaluation/validate_submission.py runs/v1-rules/submission.csv
.\.venv\Scripts\python.exe -m tiki_data smoke --csv runs/v1-rules/submission.csv --out runs/v1-alignment
```

The smoke report uses the public 7,500 frames only. Use it to check frame
alignment and label interpretation. Do not use it to choose features, weights,
smoothing, decoder costs, or a winning algorithm. It is not full-match accuracy.

## Connect P1, P2 and P3

Read [INTERFACES.md](INTERFACES.md). JSON paths resolve relative to the JSON file,
including an alternative configuration passed to `reproduce`.

`run` supports five predictor kinds:

| Kind | Input and behavior |
|---|---|
| `baseline` | Existing ATD baseline, explicit window, optional explicit metadata/raw paths and pitch |
| `labels` | Validate and import an existing CSV for integration/scoring; this cannot prove inference reproduction |
| `probabilities` | Read a validated probability NPZ; use argmax or the explicit decoder adapter |
| `adapter` | Call the rules/emissions adapter with a `MatchSpec` |
| `model` | Load/compute P1 features, check P2's expected feature order, call P2 inference |

An optional `decoder` takes the probability batch and returns labels. Omitting it
uses argmax in `H,A,D` order (ties choose the first state). Configured decoder
failure is fatal. No implicit switch to argmax or to rules occurs. Each method
name is a descriptive experiment tag; owners must ensure it accurately describes
the actual algorithm.

Example **production handoff configuration**, to adapt after P1–P3 supply their
real modules, trained feature order, and weights:

```json
{
  "schema_version": 1,
  "match": {"match_id": "BAR-ATH", "n_frames": 199319, "fps": 25},
  "method": "tcn_viterbi",
  "data_kind": "supplied",
  "seed": 42,
  "predictor": {
    "kind": "model",
    "features": {
      "callable": "team_p1.features:build",
      "inputs": {"tracking": "../data/tactical/BAR-ATH_tactical_atd.txt",
                 "metadata": "../data/tactical/BAR-ATH_tactical_atd.xml"}
    },
    "model": {
      "callable": "team_p2.inference:predict",
      "inputs": {"weights": "../artifacts/tcn/weights.npz"},
      "expected_features": ["ball_x_m", "ball_y_m", "ball_speed_mps"]
    }
  },
  "decoder": {"callable": "team_p3.decoder:decode", "settings": {}}
}
```

The module names and feature names above are illustrative, **not agreed P1/P2
implementations**. Put this configuration under `configs/` so the relative paths
shown resolve correctly. No neural framework is added to P4's environment; P2
must supply and pin its actual inference dependencies. Declare every file an
adapter reads in `inputs`, including weights and preprocessing state. Settings
hold JSON parameters, not hidden file dependencies or credentials. Adapters may
not load ground truth during inference.

For pre-exported features, replace `features` with `{"file": "path/features.npz"}`.
For pre-exported model probabilities use
`"predictor": {"kind": "probabilities", "path": "path/probabilities.npz"}`.
Never publish these restricted frame-level exports.

## External splits and comparisons

Declare the split **before** inspecting scores. `group_id` identifies the
underlying match, including any full/detected/other export variants. A group may
appear only once. Do not make random frame splits or count variants as independent
matches. Training/validation/test must each contain at least one match.

Save a manifest with this structure and actual dataset provenance:

```json
{
  "schema_version": 1,
  "dataset_id": "external_v1",
  "kind": "external",
  "matches": [
    {
      "match": {"match_id": "external_train_01", "n_frames": 10000, "fps": 25},
      "group_id": "provider_match_01",
      "split": "train",
      "provenance": {"dataset": "dataset name", "source": "exact dataset URL and version",
                     "label_provenance": "who/what produced the possession and dead-ball labels"},
      "ground_truth": "../data/external/train_01.csv"
    },
    {
      "match": {"match_id": "external_val_02", "n_frames": 12000, "fps": 25},
      "group_id": "provider_match_02",
      "split": "validation",
      "provenance": {"dataset": "dataset name", "source": "exact dataset URL and version",
                     "label_provenance": "label derivation, annotation source and limitations"},
      "ground_truth": "../data/external/val_02.csv",
      "predictions": {
        "rules": {"config": "val_02_rules.json"},
        "tcn": {"config": "val_02_tcn.json"},
        "tcn_viterbi": {"config": "val_02_tcn_viterbi.json"}
      }
    },
    {
      "match": {"match_id": "external_test_03", "n_frames": 11000, "fps": 25},
      "group_id": "provider_match_03",
      "split": "test",
      "provenance": {"dataset": "dataset name", "source": "exact dataset URL and version",
                     "label_provenance": "label derivation, annotation source and limitations"},
      "ground_truth": "../data/external/test_03.csv",
      "predictions": {
        "rules": {"config": "test_03_rules.json"},
        "tcn": {"config": "test_03_tcn.json"},
        "tcn_viterbi": {"config": "test_03_tcn_viterbi.json"}
      }
    }
  ]
}
```

Use real frame counts/FPS and matching configs. A `predictions` source can instead
be `{"csv": "predictions.csv"}` for an already computed ablation. All methods
must have exactly the same validation matches. Extra methods such as
`rules_viterbi` are supported if present on every validation match.

```powershell
.\.venv\Scripts\python.exe -m tiki_data check-manifest configs/external.json
.\.venv\Scripts\python.exe -m tiki_data benchmark --manifest configs/external.json --bootstrap 1000 --out runs/v1-validation
```

Manifest checking opens no label files. Validation opens train/validation labels
to detect duplicate files/contents and score validation matches; it does not
open test labels or test predictions. Known supplied-match identities, the
public ground-truth file, normalized copies of its evaluated labels, reused
groups/label files, and inference inputs pointing to labels are rejected. These
guards cannot prove that two differently named matches are independent, that
labels were ethically obtained, or that a provider's label meaning matches the
competition. The team must review provenance and conversion logic.

Reports include equal-weight **per-match** mean spellF1 and macroF1, per-match
bootstrap intervals when requested, transition errors/latency with original
frame indices, and up to two measured error-analysis priorities. If fewer than
two error categories occur, the report says only what was measured. Rates use
different denominators and do not predict causal gains. No aggregate confidence
interval or verified full-match supplied-game accuracy is inferred.

External FPS can differ. Transition tolerances use nearest-frame rounding of
0.48 and 1.0 seconds, minimum one frame; durations use actual FPS. Possession
IoU scoring remains the official algorithm. Periods are independent sequences;
provide `periods: [[start, stop], ...]` when halves/episodes are adjacent. Labels
outside these half-open ranges must be `X`. Scoring inserts ungraded separators
internally to prevent matching across independent periods or annotation gaps,
then maps transition frames back. The submitted CSV keeps its original timeline.

## Freeze and one-time external test

Choose using validation, then freeze before test evaluation:

```powershell
.\.venv\Scripts\python.exe -m tiki_data freeze --manifest configs/external.json --validation runs/v1-validation --method tcn_viterbi --out artifacts/v1-freeze.json
.\.venv\Scripts\python.exe -m tiki_data benchmark --manifest configs/external.json --split test --freeze artifacts/v1-freeze.json --bootstrap 1000 --out runs/v1-test
```

Freeze checks current validation evidence, source, environment, manifest, and
prediction dependencies. It fingerprints test **inference inputs**, without
opening test ground truth. Real external freezes require runnable baseline/model/
rules adapters, not imported labels or precomputed probabilities. Test evaluates
only the selected method. Preserve the freeze JSON and its sibling
`test_attempts/` directory together: an exclusive record is reserved before any
test label read, and a failed/interrupted test attempt also consumes it. Stop and
review an infrastructure failure instead of deleting the record and retuning.

This is a local guard against accidental repeated testing, not a security boundary.
Copying the selection into a new directory, editing tooling, or creating a new
freeze can circumvent it; these actions do not restore an untouched holdout.

## Reproduce and inspect the experiment log

```powershell
.\.venv\Scripts\python.exe -m tiki_data reproduce --run runs/v1-rules --out runs/v1-rules-repeat
.\.venv\Scripts\python.exe -m tiki_data experiments --root runs --out runs/experiments.csv
```

`reproduce` reruns inference with the same source, settings, and input bytes,
then compares the entire CSV's SHA-256. It rejects changed inputs/configuration,
changed source, tampered original output, and label-import runs. A mismatch
creates a failed `reproduction.json` and exits nonzero. Python/NumPy seeds are
set by P4; P2/P3 must also seed their own frameworks, disable nondeterministic
kernels when required, and use inference/evaluation mode.

For a teammate with the same source in another checkout, transfer the original
run evidence through an allowed private channel and point to an equivalent
configuration using that machine's asset locations:

```powershell
.\.venv\Scripts\python.exe -m tiki_data reproduce --run path/to/original-run --config configs/baseline.json --out runs/teammate-repeat
```

Machine-specific paths may change; declared input **contents**, adapter names,
feature order, match metadata, seeds, and settings must match. Environment
differences are recorded and reported; identical CSV bytes are still required.
Source fingerprints normalize Git's LF/CRLF line endings so equivalent Windows
and Unix checkouts compare correctly. Input data, weights and output hashes
remain strict byte hashes.
Actual teammate reproduction is a human acceptance step, not implied by a local
two-run check.

Each `run.json` retains success, failure, or an interrupted `running` state,
revision/dirty flag, source digest (including uncommitted/new Python files),
configuration, environment, content hashes and timing. `experiments.csv` is a
rebuildable shared index including dataset/split and comparison results. Keep
the original per-run records and reports. Runtime for imported CSVs is import
time, not model inference time; prediction source types remain in the report.

All `runs/`, `artifacts/`, NPZ artifacts, and `submission.csv` outputs are
gitignored. Do not force-add restricted data or outputs. No commit, push,
publication, or submission is performed by these commands.
