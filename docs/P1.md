# P1: tracking features V1

P1 converts raw 25 Hz player/ball tracking into the shared `FeatureBatch`
contract consumed by P2. It does not read possession labels, ball-status targets,
Smart Tagging, homography or video. P3 owns explicit tag/rule fusion.

## V1 feature set

The 19 columns in `configs/p1_v1_feature_schema.json` cover four deliberately
small groups:

- ball/player proximity: nearest and second-nearest distance per team;
- local configuration: observed players within 3 m and 5 m of the ball;
- team context: ball-to-centroid distance, width and length;
- motion/quality: ball speed, mean player speed and visible-player counts.

All geometry is calculated in pitch metres. Player ordering is irrelevant, so
temporary Metrica track slots never become model identities. A missing feature
has value zero and `observed=False`; a real physical zero has `observed=True`.
P2 appends observation flags and fits normalization using external training
matches only.

## P4 adapter

`tiki_data.p1.adapter:build` has the shared signature:

```python
def build(match: MatchSpec, inputs, settings) -> FeatureBatch: ...
```

Inputs are exactly `atd_meta` and `atd_raw`. For BAR-ATH the official pitch is
used by default. An external Metrica export must declare `settings.pitch` as
`[length_m, width_m]`.

## Export supplied-match features

Run locally from the repository root. The current participant files are flat in
`data/`; change the two paths if they are moved into `data/tactical/`.

```powershell
python -m tiki_data.p1 build-metrica `
  --atd-meta data/BAR-ATH_tactical_atd.xml `
  --atd-raw data/BAR-ATH_tactical_atd.txt `
  --out data/features/p1-v1-bar-ath
```

The new directory contains:

- `features.npz`: validated 199,319-row `FeatureBatch`;
- `match.json`: `MatchSpec` for P2 inference;
- `feature_schema.json`: exact ordered schema for review/training.

P2 can later run a trained compatible checkpoint with:

```powershell
python -m tiki_data.p2 infer `
  --features data/features/p1-v1-bar-ath/features.npz `
  --match data/features/p1-v1-bar-ath/match.json `
  --checkpoint artifacts/p2-v1/best.pt `
  --out runs/p2-bar-ath
```

The checkpoint must have been trained with the exact same feature schema and
order. A checkpoint trained with P2's older four-column synthetic fixture is
intentionally incompatible.

## External IDSSE handoff

This V1 implements Metrica ATD conversion and provider-neutral per-frame feature
calculations plus a streaming IDSSE converter. All seven IDSSE matches are
available under `data/external/idsse_processed/` as one `FeatureBatch` and one
separate label CSV per match. `BallPossession` and `BallStatus` are targets only
and never enter `values` or `observed`.

The frozen split is four complete train matches, two validation matches and one
test match. It uses one schema and identical calculations across every external
match and BAR-ATH. Do not tune this feature list from supplied-match,
public-window or external test scores.

## Research basis and V2 candidates

Tracking-based football event work treats ball-player distance as the central
possession clue and uses local player configurations for control/duel and
dead-ball context. Established tracking tutorials additionally use velocities,
team formations and pitch-control concepts. V1 keeps the robust inputs needed
for those ideas without implementing a fragile full pitch-control model.

After external validation exists, add one feature group at a time: third-nearest
distances, 10 m local counts, closing speed, acceleration, team spread or a
provider-neutral pitch-control approximation. Retain a group only when it
improves whole-match external validation consistently.
