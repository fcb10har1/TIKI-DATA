Pipeline and implementation

P1 reads IDSSE ball Frame.S in p1/idsse.py:read_ball_timeline and divides
km/h by 3.6. Metrica ATD x,y,speed is read in p1/metrica.py; a finite x/y
remains available when scalar speed is NaN. Shared compute_frame/compute_frames
in p1/features.py produce ball_speed_mps (column 0). Missing data uses
values[:, 0] = 0 and observed[:, 0] = False. These are separate arrays, not
a NaN-valued model channel. No velocity is reconstructed from positions.

Version A is the unchanged configs/p2_idsse_v1.json. B adds only:
  "p1": {"mask_ball_speed": true}
in configs/p2_idsse_no_ball_speed.json. The shared P1 apply_feature_policy
supports both providers and existing cached batches without mutating originals.
The raw P1 build-metrica/build-idsse commands also accept --mask-ball-speed;
the P4 P1 adapter accepts settings.mask_ball_speed. IDSSE export now resolves
paths relative to the chosen output/config location so a separate B export
cannot accidentally refer back to A, and resume rejects a policy mismatch.

P2 load_data applies the P1 policy before normalization/window creation.
fit_normalization uses observed, in-period TRAINING frames only. An explicitly
disabled speed channel receives mean 0, scale 1, count 0. Other entirely
unobserved features still fail by default. encode concatenates 19 normalized
values and 19 observed flags (38 channels); hidden speed occupies channels
0 and 19, both zero. All other feature moments are unchanged.

The masking policy is saved inside checkpoint normalization and enforced by
predict_batch, including for a new unmasked FeatureBatch. An inference setting
cannot re-enable speed for B. A can be evaluated without speed through the
P1 policy or p2 infer --mask-ball-speed. No architecture change was made.
